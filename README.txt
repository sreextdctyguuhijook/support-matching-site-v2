--------------------------------
1. GitHub 새 저장소 만들기
--------------------------------

1. GitHub에 접속합니다.
2. New repository를 선택합니다.
3. 저장소 이름을 입력합니다.
4. Create repository를 누릅니다.
5. 위의 파일 4개를 저장소 최상위에 업로드합니다.

파일이 저장소의 첫 화면에서 바로 보여야 합니다.

--------------------------------
2. Render 새 서비스 만들기
--------------------------------

1. Render에 접속합니다.
2. New + 를 누릅니다.
3. Web Service를 선택합니다.
4. 방금 만든 GitHub 저장소를 연결합니다.
5. Runtime은 Node를 선택합니다.

설정값:

Root Directory:
비워 두기

Build Command:
npm install

Start Command:
npm start

설정을 저장하고 Deploy합니다.

--------------------------------
3. 기존 API 인증키 유지하기
--------------------------------

기존 Render 서비스의 Environment 메뉴에서
현재 API 인증키 환경변수 이름을 확인합니다.

이 코드가 인식하는 환경변수 이름:

DATA_GO_KR_SERVICE_KEY
DATA_API_KEY
SERVICE_KEY
API_KEY
OPEN_API_KEY
KEY
DATA_GO_KR_KEY

기존 환경변수 이름이 DATA_GO_KR_SERVICE_KEY라면
새 Render 서비스에도 같은 이름으로 등록합니다.

기존에 다른 이름을 사용하고 있었다면
그 이름과 기존 인증키 값을 그대로 등록해도 됩니다.

주의:
새 Render 서비스는 기존 서비스의 환경변수를
자동으로 복사하지 않을 수 있습니다.

인증키를 HTML이나 GitHub 코드에 직접 입력하지 마세요.
채팅으로 인증키를 보낼 필요도 없습니다.

새 사이트가 정상 작동하는 것을 확인하기 전까지
기존 Render 서비스는 삭제하지 마세요.

--------------------------------
5. 데이터 및 필터 안내
--------------------------------

서버는 공공데이터 API를 페이지당 최대 100건,
최대 10페이지까지 요청하도록 구성되어 있습니다.

실제 수집 건수는 API 제공기관의 응답,
인증키 권한 및 데이터 제공 정책에 따라 달라집니다.

현재 필터는 공고 제목과 본문에 포함된
키워드를 기준으로 검색합니다.

따라서 실제 신청 자격을 확정적으로 판정하는 기능은 아닙니다.
신청 전 반드시 공식 공고문을 확인해야 합니다.

API 연결에 실패해도 서버 상태 확인 기능과
웹사이트 화면은 별도로 유지됩니다.
